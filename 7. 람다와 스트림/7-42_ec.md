# 익명 클래스보다는 람다를 사용하라

익명 클래스 방식은 코드가 너무 길기 때문에 자바는 함수형 프로그래밍에 적합하지 않았다.

자바8에 와서 추상메서드 하나짜리 인터페이스는 특별한 의미를 인정받아 람다식을 사용할 수 있게 되었다.

```java
Collections.sort(word, new Comparator<String>() {
	public int compare(String s1, String s2) {
		return Integer.compare(s1.length(), s2.length());
	}
}
```

```java
Collections.sort(words, (s1, s2) -> Integer.compare(s1.length(), s2.length())));
```

람다는 타입을 명시하지 않지만 ‘타입을 알 수 없다’라는 오류를 제외하고는 모두 타입을 생략하는 것이 좋다.

이전에 다뤘던 Enum에 메서드를 통한 코드가 있다.

```java
public enum Operation {

	PLUS(“+”) {
		public double apply(double x, double y) { return x + y; }
	},

	MINUS(“-“) {
		public double apply(double x, double y) { return x - y; }
	}

	…

	public abstract double apply(double x, double y);
}
```

이 코드를 람다식을 활용하면 아래와 같이 간결해진다.

```java
public enum Operation {
	PLUS(“+”, (x, y) -> x + y),
	MINUS(“-“, (x, y,) -> x-y),
	…

	Operation(String symbol, DoubleBinaryOperator op) {
		…
	}
}
```

람다는 장점이 많지만 이름이 없고 문서화도 못 한다. 따라서 코드 자체로 동작을 명확히 설명할 수 없거나 코드 줄 수가 너무 많으면 사용하지 않는 것이 좋다. 또한 람다는 직렬화하는 일은 삼가야 한다.
